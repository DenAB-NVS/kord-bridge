## Уроки технические

1. **Роли берегов закреплены:** VPS — мозг и исполнитель GitHub-задач, но НЕ канал до Telegram: MTProto с сервера закрыт наглухо (DC2/DC4:443 — таймауты, прямые порты тоже). Отправка юзерботом — только с Termux (телефон) или через прокси.
2. **Рабочая схема доставки:** я кладу задание в `очередь/` → сервер исполняет → эхо в `kord-echo` → я читаю. Файлы рассылки приезжают на телефон rsync'ом с сервера, отправка идёт с телефона. Полный круг: GitHub → VPS → Termux → Telegram.
3. **Служба kord-myst живёт неровно:** ручной прогон параллельно со службой оставляет git-замки (`index.lock`) и циклы теряются; служба может молчать часами. Лечение: `rm -f ~/kord-echo/.git/index.lock` и `bash ~/kord-cikl.sh`. Ручной прогон снаружи: `ssh root@45.152.198.192 "bash /root/kord-cikl.sh"`.
4. **Termux после обновления питона ломает пайп** (3.12 → 3.13): «unable to open python3.12». Лечение одной цепочкой: `pkg upgrade -y` → `python -m ensurepip` → `python -m pip install telethon`.
5. **Отчёт важнее лога:** stdout под nohup буферизуется, лог отстаёт; источник истины — `отчёт-рассылки.txt`, он пишется после каждой отправки.
6. **Идемпотентность отправщика обязательна:** строка `OK` в отчёте = контакт пропускается при перезапуске. Дублей нет, любой перезапуск безопасен.
7. **Секреты — никогда в мост:** api_id/api_hash и сессии не коммитятся; сервер ищет ключи сам по `/root`, конфиг с правами 600, сессии копируются `cp`/`rsync` вне репозитория.
8. **Процесс убивать перед перезапуском:** `pkill -f otpravka.py` — два параллельных отправщика портят отчёт гонкой.
