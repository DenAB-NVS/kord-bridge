# Задание 0073 — СТОРОЖ ВЕНЫ v1

**Цель:** вена (VPN телефона → туннель → api.telegram.org) больше не умирает тихо. Если Telegram молчит дольше порога — рука будит владельца уведомлением.

**Законы:** скрипт пишет ТОЛЬКО в свои файлы (`vena-watchdog.log`, `.vena-watchdog-*`) — общие эхо не трогает (шов ночи 05→06: в одном такте выживает последнее задание). Откат — удаление одной строки планировщика и одного скрипта. Ничего не удаляет, никого не будит без причины, на сервер не ходит.

## Шаг 1 — разведка (read-only)

```
crontab -l
ps -ef | grep -iE 'vena|cycle|kord|рука' | grep -v grep
command -v termux-notification; command -v termux-toast
```

Цель: понять, чем крутится пульс (cron или цикл-скрипт), и есть ли Termux:API. Результаты — в эхо шага 5.

## Шаг 2 — создать скрипт

```
cat > $HOME/vena-watchdog.sh <<'VENAEOF'
#!/data/data/com.termux/files/usr/bin/bash
# СТОРОЖ ВЕНЫ v1 — задание 0073 (ночь 06→07.10.2026)
# Смотрит живость api.telegram.org через VPN телефона.
# Пишет только в свои файлы. Общих эхо не касается.
# Откат: удалить строку из планировщика + rm этого файла.

LOG="$HOME/vena-watchdog.log"
STATE="$HOME/.vena-watchdog-fails"
NOTIF="$HOME/.vena-watchdog-notified"
LIMIT=3        # проверок подряд до будильника
COOLDOWN=1800  # не будить чаще раза в 30 минут

ts() { date '+%Y-%m-%d %H:%M:%S'; }

code=$(curl -m 10 -s -o /dev/null -w '%{http_code}' https://api.telegram.org 2>/dev/null)
if [ -n "$code" ] && [ "$code" != "000" ]; then
  echo 0 > "$STATE"; exit 0
fi

# интернет жив, а Telegram молчит — это вена
if ! ping -c 1 -W 5 1.1.1.1 >/dev/null 2>&1; then
  echo "$(ts) сам интернет лежит — вена ни при чём, не будим" >> "$LOG"; exit 0
fi

c=$(cat "$STATE" 2>/dev/null); c=${c:-0}; c=$((c+1)); echo "$c" > "$STATE"
echo "$(ts) вена молчит (проверка $c из $LIMIT)" >> "$LOG"

if [ "$c" -ge "$LIMIT" ]; then
  now=$(date +%s); last=$(cat "$NOTIF" 2>/dev/null); last=${last:-0}
  if [ $((now-last)) -ge $COOLDOWN ]; then
    echo "$(ts) ВЕНА ЛЕЖИТ — будим владельца" >> "$LOG"
    echo "$now" > "$NOTIF"
    termux-notification --title "СТОРОЖ ВЕНЫ: вена лежит" \
      --content "api.telegram.org молчит ~$((LIMIT*5)) минут. Включи VPN телефона; при необходимости перезапусти туннель." \
      --priority high --vibrate 300,200,300 2>>"$LOG" || \
    termux-toast "ВЕНА ЛЕЖИТ — включи VPN" 2>>"$LOG"
  else
    echo "$(ts) будильник на кулдауне" >> "$LOG"
  fi
fi
VENAEOF
chmod +x $HOME/vena-watchdog.sh
```

## Шаг 3 — тест на живой вене

```
bash $HOME/vena-watchdog.sh; echo "exit=$?"
cat $HOME/vena-watchdog.log 2>/dev/null
```

Ожидание: `exit=0`, лог пустой — вена сейчас жива, сторож должен промолчать. Если что-то не так (нет curl, ошибки синтаксиса) — записать в эхо и остановиться, обходные пути не городить.

## Шаг 4 — подключить к пульсу

- Если шаг 1 нашёл cron: добавить строку `*/5 * * * * bash $HOME/vena-watchdog.sh >/dev/null 2>&1` и проверить `crontab -l | grep vena`.
- Если пульс крутится цикл-скриптом: добавить вызов `bash $HOME/vena-watchdog.sh` отдельной строкой в начало цикла. Скрипт тихий и в общий файл эха не пишет — шов не заденет.
- Путь, чем именно подключено, — в эхо шага 5.

## Шаг 5 — эхо (свой файл, новый закон)

Создать `телефон/эхо/0073-сторож-вены.md`: что нашлось в шаге 1, чем подключено (cron или цикл), вывод шага 3, как отключить. Не писать в общие эхо.

## Откат

Удалить строку из cron/цикла; `rm $HOME/vena-watchdog.sh $HOME/vena-watchdog.log $HOME/.vena-watchdog-*`; удалить эхо-файл 0073. Дом и сервер не затронуты ни на одном шаге.

**Стоп-правила:** на сервер в этом задании не ходим. VPN не переключаем. Уведомление — только средствами, уже имеющимися на руке; если Termux:API нет, v1 ограничивается логом, а будильник — вопрос v2 по слову владельца.
